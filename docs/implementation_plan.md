# 1~3단계 구현 계획 및 요구사항 추적

기준: Group3_MultiAgent_Development_Guide.md. 사용자 작업 순서의 1~3단계(가이드 8장의 단계 번호와 다름)만 수행한다.

## 확정 및 원본 요구

| 요구 | 이번 구현/후속 단계 |
|---|---|
| 기본 8편, 최소 7편, 가변 개수 | 환경 설정과 요청 Pydantic 검증, 3편 smoke 실행 |

## 권장 구현의 구체화 및 변경 이유

- 영어 토큰 기준 coverage: 0.75 이상 high, 0.5 이상 medium, 미만 제외. 사전 문서화된 결정론적 기준으로 테스트 가능하게 한다. arXiv 자체 순서를 절대 점수로 취급하지 않는다. 한국어/의미적 동의어 검색은 보장하지 않으며 Ranker Protocol 교체 대상으로 둔다.
- 최신성 기준은 최초 제출일 기본, 수정일로 설정 교체 가능. 후보 3배수 기본. 유한 후보 풀 소진 시 부족 결과를 반환하며 무관한 논문으로 채우지 않는다.
- 로컬 JSON+태스크 manifest를 사용한다. 권장 SQLite 인덱스는 초기 3편 검증에 불필요하므로 생략. 공용 인터페이스를 교체해 원격 저장소로 이전 가능하다.
- PDF 파싱에 임의 텍스트 추출 대체를 사용하지 않는다. GROBID 미가동이면 명시적 실패로 남긴다.
- HTTP 재시도는 타임아웃/연결 실패/429/5xx만 제한적으로 수행. 논문 원문은 실행 간 캐시 재사용 없이 실행별 디렉터리에 보존한다.

## 팀 협의 — 모두 임시 v0.1 계약

1. 그룹 1: A2A SDK·프로토콜 버전, Agent Card, task 상태 및 오류 매핑, 타임아웃/취소, input-required. 로컬 status를 A2A 표준 상태라고 주장하지 않는다.
2. 그룹 2: Paper Store 배치·접근 URI·권한, section/evidence 식별자, Reader 및 Connections 전체 스키마. 이번에는 추측한 분석 필드를 만들지 않는다.
3. 전체: 참고문헌 정규화/동률 정책, Markdown 목차·출처 형식, 저장 기간·배포 정책.
4. 그룹 1: Coverage 1회 재시도 후 처리, Evidence/Chroma 연결 책임. 후속 Writer에서 교체 가능한 정책으로 구현 예정.

## 순서 및 검증

1. 가이드 분석 및 본 계획 작성.
2. 설정·공통 Pydantic 모델·검색/순위/저장 Protocol 구성.
3. Agent 1 검색 → 순위 → 순차 다운로드 → HTML 또는 GROBID → 원본/JSON/manifest 저장.
4. Mock: 개수 3/5/7/8/12 및 부족, 순위, 중복, HTML 실패/TEI 대체, 재시도·간격·원문 추적·저장/조회 검증.
5. Live: 실제 영어 연구 주제로 3편 전체 파이프라인 실행. 네트워크/GROBID 실패와 성공을 별도 기록. 이후 기본 8/7 검증은 성공한 3편 실행과 구분한다.
